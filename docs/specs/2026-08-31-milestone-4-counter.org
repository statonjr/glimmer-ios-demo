#+title: Milestone 4: the counter on the simulator — design
#+author: Larry Staton (with Claude)
#+date: 31 August 2026

* Purpose

Run the macOS demo's counter on the iOS simulator over the glimmer seam: the
counter's /view/ unchanged, its dispatch rewired one line per button, its state
atom become a ratom. This is the demonstration the whole notebook has been
building toward — the README's revised milestone 4 — and it subsumes what is
left of milestones 0 and 3: glimmer as a dependency, the nine backend functions,
and the =:schedule= path with the =swap-vals!= correction.

Done means: =NS=demo.examples.counter jolt bundle && jolt install && jolt launch=
shows the counter on an iPhone 17 simulator; tapping =+ 1= increments the label;
a programmatic smoke proves the same round trip without a finger and prints
={:count 2}=; =jolt test= is green on the host; =clj-kondo= reports 0/0.

* Context this design stands on

Decided already, in README.org, and not reopened here:

- *Option C*: implement =glimmer.backend='s nine functions over UIKit; glimmer
  owns reactivity, components and reconciliation and declares no natives.
- *Ancestor*: =jolt-lang/glimmer-uikit= (the AppKit backend, v0.1.0 lineage),
  not =glitter-uikit=. Its =GlimmerTarget= pattern, =objc_msgSend= arity table
  and Pango-markup pipeline are the machinery this design reuses.
- *Two corrections carried forward*: the scheduler drain uses =swap-vals!=;
  =loop-running?= is set before the mount.
- *Proven on the simulator* (milestones 1–3): cross-compiling with
  =jolt build --target tarm64ios=; =jolt.ffi= loads; =objc_getClass= round-trips
  once UIKit is dlopen'd /inside =-main=/; =UIApplicationMain= with a
  runtime-built delegate puts a =UIWindow= up; a =:uint8= (not =:char=) is how a
  =BOOL= comes back from a foreign-callable.

Decisions made in the brainstorm (2026-08-31):

| decision | choice |
|----------+--------|
| target | the macOS demo's counter, verbatim view (=:markup=, =:homogeneous=, =:margin=), registry-dispatched |
| where the backend lives | this repo, =src/glimmer_ios/=; extraction to a library later |
| notebooks | per-namespace org files tangling into =src/=; README.org is the spine |
| how it is built | fork glimmer-uikit's machinery verbatim where iOS does not change it; write only the seam |

No =:jolt/native=. UIKit is loaded by =glimmer-ios.core/load-uikit!= from inside
=-main=; the cross build loads every namespace on the host first, and a
top-level =load-library= of a framework macOS lacks kills the build (milestone 3).

* The app loop and the scheduler (=glimmer-ios.core=)

** =:run=

=run*= is the milestone-3 spike generalized to the backend contract
=(fn [opts mount-root!])=:

1. =load-uikit!=; register =GlimmerAppDelegate= once (guarded by
   =objc_getClass=, like glimmer-uikit's =invoker=).
2. Stash =mount-root!= in an atom the IMP can reach. =UIApplicationMain=
   instantiates the delegate itself by class /name/, so the callback cannot
   close over anything.
3. =(reset! b/loop-running? true)= *before* =UIApplicationMain=. This is
   glimmer-gtk's ordering; it makes glimmer-uikit's set-after-mount bug
   impossible here, because the flag is true before the callback can run.
4. =UIApplicationMain(1, argv, nil, "GlimmerAppDelegate")= — =:blocking=; never
   returns.

** The delegate callback

=application:didFinishLaunchingWithOptions:= (a =:collect-safe=
foreign-callable returning =:uint8=): =[[UIWindow alloc] init]=, a
=UIViewController=, then =(mount-root! (view-of vc) :window)=, then
=makeKeyAndVisible=. The window is held in an atom.

The root container tag is =:window=. =append-child!= for =:window= adds the
child to the controller's view and pins it to =safeAreaLayoutGuide= — top,
leading, trailing — not to the view's edges, so the counter's caption does not
sit under the Dynamic Island. Bottom is left free (the stack hugs its content).

** =:schedule=

The CFRunLoopSource scheduler from glimmer-uikit, with two changes:

- The drain: =(let [[jobs _] (swap-vals! queue (constantly []))] …)= — the
  glitter-uikit P3.T2 correction. A concurrent =(swap! queue conj work)= either
  lands in =jobs= or survives for the next signal; the deref-then-reset original
  could lose it silently.
- Created lazily on first =schedule= (a =delay=), not at namespace load, because
  namespace load happens on the host during =jolt build=.

=CFRunLoopGetMain=, =CFRunLoopSourceCreate=, =CFRunLoopAddSource=,
=CFRunLoopSourceSignal=, =CFRunLoopWakeUp= and the =CFRunLoopSourceContext=
layout are CoreFoundation and identical on iOS. =kCFRunLoopDefaultMode= is
created with =CFStringCreateWithCString= as glimmer-uikit does.

** Dropped

=quit!=, =:auto-quit-ms=, =terminate-app!= (an iOS app neither quits nor may
=exit()=); the nREPL main-thread hop in =run!= (no =jolt nrepl-server= inside a
bundle); =:tooltip=; the =:window= /tag/ (the root container kind stays).

=:reorder-child!= is kept — =insertArrangedSubview:atIndex:= exists — so keyed
reconciliation is complete even though the counter never reorders.

* The widget layer (=glimmer-ios.widget=)

** Containers: =:vbox= / =:hbox= → =UIStackView=

Same alias/orientation sugar as glimmer-uikit. Prop mapping:

| prop | UIKit call |
|------+------------|
| =:spacing= | =setSpacing:= (double) |
| =:homogeneous= | =setDistribution:= — =FillEqually= (1) / =Fill= (0) |
| =:orientation= | =setAxis:= — =Vertical= (1) / =Horizontal= (0); the selector is not AppKit's =setOrientation:= |
| =:margin= and =:margin-top/-left/-bottom/-right/-start/-end= | =setLayoutMargins:= (=UIEdgeInsets=: four doubles, HFA in d0–d3) *and* =setLayoutMarginsRelativeArrangement:YES= |
| =:halign= / =:valign= | =setAlignment:= on the parent stack — leading 1, center 3, trailing 4 |
| =:hexpand= / =:vexpand= | =setContentHuggingPriority:forAxis:= |

Children: =addArrangedSubview:=, =removeArrangedSubview:= followed by
=removeFromSuperview= (UIKit keeps a removed arranged subview as a plain
subview otherwise), =insertArrangedSubview:atIndex:=.

The README's prediction — =UIStackView= ignores =layoutMargins= unless
=isLayoutMarginsRelativeArrangement= is YES — is why both calls are made.

** =:label= → =UILabel=

=setText:=, =setAttributedText:=, =setTextAlignment:= (left 0, center 1, right
2, from =:xalign=), =setNumberOfLines:= (0 for =:wrap=), =setLineBreakMode:=
for =:ellipsize=.

** =:button= → =UIButton=

=buttonWithType:= system (1), =setTitle:forState:= normal (0), =setEnabled:=.
Events: =addTarget:action:forControlEvents:= with =TouchUpInside= (1 << 6),
target the shared =GlimmerTarget= instance, action =fire:=. The pointer-keyed
=actions= registry and the =:collect-safe= IMP are glimmer-uikit's, unchanged.
Only =:on-click= is wired; the =signals= atom keeps the extension shape.

** Markup → attributed string

=markup=, =markup-string=, =escape-markup=, the Pango vocabulary validation,
=markup->segments=, entity decoding and Pango size names are verbatim. What
changes is confined to two functions:

- =style-font=: =UIFont systemFontOfSize:weight:= (bold = =UIFontWeightBold=,
  0.4, a double) and =italicSystemFontOfSize:=; base size 17 (UIKit body), not
  13.
- =color-hex=: =UIColor colorWithRed:green:blue:alpha:=.

Attribute-name constants (=NSFontAttributeName=, =NSForegroundColorAttributeName=,
=NSStrikethroughStyleAttributeName=, =NSUnderlineStyleAttributeName=) are
=NSString= globals read through =dlsym=, as glimmer-uikit does; they are the
same names on iOS.

** =:text->element=

Default kept: a bare string child renders as =[:label {:label s}]=.

* The counter (=examples/counter/README.org=)

** =demo.registry=, trimmed

The action pipeline only: =action-spec= (multimethod, dispatch =first=),
=::action= as an =s/multi-spec=, =::actions=, =run-action!= (multimethod on
=(first action)=) with a =:default= that prints, and =execute-actions= that
validates then runs. Dropped: the example registry (=register-example!=,
=examples=), =event-value=, =core/set-dispatch!= — glitter's event-map shape;
under glimmer a button delivers nothing but the click.

** =demo.examples.counter= — the diff worth printing

#+begin_src clojure :tangle no
(defonce state (r/atom {:count 0}))                 ; ← was clojure.core/atom

(defn view [{:keys [count]}]                        ; unchanged
  [:vbox {:spacing 12 :margin 16}
   [:label {:markup [:span {:size "small" :foreground "#8e939d"} "COUNT"]}]
   [:label {:markup [:span {:size "xx-large" :weight "bold"} (str count)]}]
   [:hbox {:spacing 8 :homogeneous true}
    [:button {:label "+ 1"   :on-click #(reg/execute-actions nil [[:action/inc]])}]   ; ←
    [:button {:label "Reset" :on-click #(reg/execute-actions nil [[:action/reset]])}] ; ←
    [:button {:label "- 1"   :on-click #(reg/execute-actions nil [[:action/dec]])}]]]) ; ←

;; the six defmethods: unchanged

(defn root [] (view @state))                        ; ← new: the reactive root
(defn -main [& _] (ui/run root :title "Counter"))   ; ← replaces register-example!
#+end_src

Four arrows in the view and state; the =register-example!= call becomes
=-main=. Everything else is the macOS demo's text. The deref inside =root= is
what makes it reactive: glimmer tracks the ratom read and re-renders =root= on
=swap!=, reconciling the label in place.

** Data flow

#+begin_src mermaid :tangle no
sequenceDiagram
    participant U as UIButton
    participant T as GlimmerTarget (fire: IMP)
    participant R as demo.registry
    participant S as ratom state
    participant G as glimmer.core
    participant Q as :schedule (CFRunLoopSource)
    participant L as UILabel
    U->>T: TouchUpInside → fire:
    T->>R: (execute-actions nil [[:action/inc]])
    R->>R: s/valid? ::actions
    R->>S: (swap! state update :count inc)
    S->>G: watcher: root is dirty
    G->>Q: loop-running? → schedule re-render
    Q->>G: perform (main run loop)
    G->>L: apply-props! :markup "…2…"
#+end_src

On the main thread the schedule hop is a no-op in effect — the thunk runs on
the next loop turn — but it is the same path an off-thread write takes, so the
counter exercises the scheduler every tap.

* Verification

- *Headless, host*: =jolt test= runs glimmer-uikit's =widget_test.clj= ported to
  =glimmer-ios.widget= (escape, render-from-hiccup, coercion, orientation
  injection, Pango rejection). Nothing in it touches UIKit; it runs on macOS
  and Linux CI. =clj-kondo --lint src test= at 0 errors, 0 warnings; the
  tangled =.clj-kondo/config.edn= already covers the FFI macros.
- *Simulator, no finger*: =demo.smoke= runs the counter and, one second after
  launch, schedules through the backend's own =:schedule= a thunk that locates
  the =+ 1= button via =glimmer-ios.core/root-inst= and glimmer's instance
  tree, calls =sendActionsForControlEvents:= (TouchUpInside) on it twice, then
  prints =@state=. Expected on =jolt console=: ={:count 2}=. This proves the
  full round trip in the diagram above, including the marshalling the scheduler
  exists for.
- *Simulator, eyes*: =simctl io screenshot= after the smoke; the chrome
  screenshot for =media/= is Larry's.
- *Recorded*: results and mistakes go into README.org's milestone 4 section, in
  the notebook's style.

* Risks and things expected to bite

- *=os.name= is "Linux" on iOS* (milestone 1). Nothing in this design reads
  =errno= or gates on =os.name=; the guard is /where the load happens/. If any
  =jolt.ffi= path consults =errno-loc= it resolves =__errno_location= and fails —
  the upstream issue is already noted in README.org.
- *UIKit's main-thread checker* is stricter than AppKit's. Every widget call
  happens inside the delegate callback or a scheduled thunk, both on the main
  thread; the smoke deliberately goes through =:schedule=.
- *Legacy delegate lifecycle on iOS 26*: no scene manifest in =Info.plist= gave
  =didFinishLaunchingWithOptions:= in milestone 3; the SpringBoard log grumbles
  about scene updates but the app runs. If a future runtime refuses, the fix is
  a =UISceneDelegate= built the same way — out of scope here.
- *HFA struct arguments* (=UIEdgeInsets=, =CGRect=) pass as four doubles; no
  struct is /returned/ anywhere in this design.
- *glimmer-uikit's =terminate-cb= returns =1= as =:char=* — the latent bug found
  in milestone 3. Nothing here copies it; every =BOOL= return is =:uint8=.
