#+title: Flappy Bird on iOS
#+author: Larry Staton
#+date: 31 August 2026

A second example, and a second renderer. The counter proved the glimmer seam
over UIKit; this one asks whether [[https://github.com/raysan5/raylib][raylib]] — a C game library, bound from jolt
over its bare C ABI by [[https://github.com/jlt-commons/raylib-jlt][raylib-jlt]] and [[https://github.com/jlt-commons/raygui-jlt][raygui-jlt]] — can draw on an iPhone. The
target is not a port of those examples but something better shaped: the
[[https://github.com/jasalt/jolt-android-experiment][jolt-android-experiment]]'s Flappy Bird ([[https://github.com/jasalt/jolt-android-experiment/tree/6d2b291d8098d8abc76431b6d9f851b9ee329934/experiments/RAY-018-flappy-bird][RAY-018]]) is a /pure/ =.cljc= — no
polling, no drawing, no native values; an owner loop hands it an input snapshot
and a delta and draws what comes back. Its own README says the point of that
shape is that "the same .cljc domain … code could run under Jolt on Linux,
macOS, and potentially iOS." This notebook tests the sentence: *their
simulation, unchanged, an iOS owner loop underneath.*

Like the main notebook, this starts as the research that says the attempt is
worth making, and accretes the experiment as it happens. Nothing tangles yet.

* Research findings (2026-08-31)

** What Android already proved, experiment by experiment

Read at =6d2b291=, the RAY series is a ladder, and most rungs carry over:

- *RAY-002* — raylib builds /statically/ into the host image with its Android
  platform layer (=android_main → main=); dynamic deps are only the platform's
  (=EGL=, =GLESv2=, =OpenSLES=, =log=, =c=, =m=, =dl=). Assembly first, before
  any managed runtime, so failures stay attributable.
- *RAY-005/006* — jolt as a /library/ (=jolt build --library=, =ffi/export!=,
  =jolt_library_init= / =jolt_lookup= / =jolt_library_shutdown=), =dlopen='d by
  the C host and entered on the host's own thread. Everything — init, lookup,
  calls, shutdown — on one OS thread.
- *RAY-007, "Topology A"* — jolt's FFI resolves raylib symbols from the
  /already-loaded process image/: one raylib, statically linked into the host,
  found through a =:jolt/native= entry marked =:optional true= (so the cross
  build does not try to load it) with =--export-dynamic= on the host. A pure
  =:process true= declaration was tried first and did not suffice there
  (=process-only-reduction.txt=).
- *RAY-009* — the part that matters most: after the host enters jolt once,
  *jolt owns the loop*. =InitWindow=, =WindowShouldClose=, =BeginDrawing=,
  =EndDrawing=, =CloseWindow= — all called from Clojure, on the
  native-app-glue thread, for 905 seconds, across a lock/unlock. No C callback
  re-enters jolt per frame. (A variadic =TraceLog= call killed the process and
  was removed — no variadics across the FFI.)
- *RAY-010* — touch through raylib's /scalar/ API (=GetTouchPointCount=,
  point-zero x/y, touch-as-mouse press/down/release), kept out of portable
  state; =GetTouchPosition= returns =Vector2= /by value/ and was deferred to a
  separate aggregate-ABI experiment (RAY-012).
- *RAY-017/018* — a debug nREPL into the running host, and Flappy Bird: the
  pure =.cljc= (19 tests, 96 assertions on the host), a press-/edge/ flaps, the
  delta clamped to 50 ms so a resume cannot teleport the bird. Drawing and
  input stay in the owner loop.

Their conclusion, carried forward whole: keep the simulation pure, keep native
values out of it, let one thread own raylib, and prove assembly before
behaviour.

** Where iOS differs, and where it does not

*The binary is ours.* Android's topology is embedded-core: a C host, jolt as a
library. This project's is inverted — =jolt build --target= emits the whole
executable, and it is /Chez/ that owns =main=. That is a simplification here,
not a complication: no =jolt_lookup=, no export table, no second image to
resolve symbols from. raylib becomes a static archive in the target pack and a
=-lraylib= on the link line, exactly as =libffi.a= did in milestone 5, and every
=defcfn= resolves against the process at first call. (If the bindings are taken
as a dependency rather than copied, their =:jolt/native= naming =libraylib.dylib=
is the GTK4 wall again; the copy-the-subset move this notebook already made with
glimmer-uikit avoids the question, and jolt's =:process true= is the other
door.)

*raylib has no iOS platform layer.* =src/platforms/= at upstream head is
android, desktop_glfw, desktop_rgfw, desktop_sdl, desktop_win32, drm, web —
and =rcore_template.c=. Issue #330, "Try to support iOS platform", closed in
2018 without one. A from-scratch =rcore_ios.c= is a UIWindow, a GLES layer
(rlgl already speaks GLES2 — that is the Android build), touch, and the loop:
several hundred lines of Objective-C/C, with =rcore_android.c= as the model.

*The shortcut is SDL.* raylib's =PLATFORM_DESKTOP_SDL= backend exists, and SDL
supports iOS properly — UIKit window, GLES and Metal, touch reported as mouse
by default, orientation, the lot. Building SDL for iOS is well-trodden; raylib
on SDL on iOS is not, but it collapses the platform layer to "build SDL", and
it keeps the thing RAY-009 proved: SDL on iOS permits a /blocking/ main loop
(it spins the run loop from inside =SDL_PumpEvents=), so raylib-jlt's
=(while (not (should-close?)) …)= may survive as written. The recommended form
is =SDL_iPhoneSetAnimationCallback= — a frame callback — which is this
notebook's =:collect-safe= foreign-callable shape if the blocking loop turns
out to misbehave in the background.

*How =main= meets =UIApplicationMain=.* SDL's own =main= calls
=SDL_UIKitRunApp(argc, argv, SDL_main)=, which runs =UIApplicationMain= with
SDL's delegate and calls =SDL_main= from inside it. Chez owns =main= here, so
the plan is to call =SDL_UIKitRunApp= /ourselves/ through the FFI, =:blocking=,
passing a =:collect-safe= foreign-callable as =SDL_main= — which is
=screen.core= exactly: a blocking call into UIKit's loop, a callback that runs
inside it, and the whole raylib loop living in that callback. Untested; this is
the first real question.

*Portable bytecode and structs by value.* On the phone every foreign call goes
through libffi. raylib passes =Color=, =Vector2=, =Rectangle= by value in nearly
every signature — the aggregate ABI that RAY-010 deferred and RAY-012 took on
for Android. libffi handles arm64 by-value aggregates, and raylib-jlt already
binds =[:by-value …]= (its 0.7.23 floor), so the expectation is "works"; it is
still the cheapest decisive probe and goes first.

*Loop ownership under iOS lifecycle.* iOS suspends a backgrounded app mid-loop
and resumes it in place — the Lifecycle section found the parked Chez thread
does nothing remarkable across that. A blocking raylib loop should be the same
case. RAY-018's 50 ms delta clamp is what makes the resume invisible to the
bird; it comes along.

** raygui, and the app as data

raygui is immediate-mode: a button is =(gui-button rect "label")= returning
whether it was pressed, called every frame. That is a second renderer for
=demo.data= — the same ={:state … :view …}= from the same negotiated wire, with
=render= emitting raygui calls instead of hiccup. The app-as-data claim
surviving a renderer swap would say more than either demo alone. Later; the
bird comes first.

** An aside: babashka grew an FFI

[[https://blog.michielborkent.nl/babashka-ffi.html][babashka.ffi]] is =java.lang.foreign= (Panama) under the hood — Mac, Windows,
Linux; callbacks; struct "places" — the same no-wrapper, no-codegen school as
=jolt.ffi=, and the same =defcfn= shape. It does not run on a phone, so it
changes nothing on the device; on the Mac it means the notebook's bb scripts
could call CoreFoundation or libimobiledevice directly instead of shelling out
to =xcrun= and =iproxy=. Noted, not pursued.

* Milestone 0: structs by value, on =pb= (2026-08-31)

The question, precisely: raylib's signatures pass =Color= (4 bytes, one
register), =Vector2= (8 bytes, a homogeneous float aggregate), =Rectangle=
(16 bytes, the largest HFA) and =Camera2D= (24 bytes — over the limit, so the
arm64 ABI passes it /indirectly/, by hidden pointer) by value, and return
=Vector2= by value (=GetTouchPosition=, =GetMousePosition=). On the simulator a
native Chez emits its own call stubs; on the phone every foreign call is a
libffi =ffi_call= with a libffi-described aggregate. Same jolt code, two
mechanisms — so the probe runs on both, and the simulator is the control.

jolt's shape for this, from the CHANGELOG: a by-value argument is
=[:by-value [:struct …]]= and the value passed is a pointer to caller-owned
struct bytes; a by-value /return/ adds a destination pointer as the jolt
function's *first* argument, filled and handed back. raylib-jlt stages its one
=Vector2= exactly so (=circle-gradient!=), which is the pattern copied here.

** A stub library that only moves structs

Nothing raylib yet — assembly before behaviour (RAY-002). Five functions whose
answers are known, with values chosen to be exactly representable in a float,
so equality is honest:

#+begin_src c :tangle ../../src/probe/by_value.c :mkdirp true
/* examples/flappy, milestone 0: raylib's struct shapes, by value, no raylib. */
#include <stdint.h>

typedef struct { uint8_t r, g, b, a; } Color;                     /*  4 bytes: one integer register   */
typedef struct { float x, y; } Vector2;                           /*  8 bytes: HFA, two float regs    */
typedef struct { float x, y, width, height; } Rectangle;          /* 16 bytes: HFA, four float regs   */
typedef struct { Vector2 offset, target; float rotation, zoom; } Camera2D;  /* 24 bytes: indirect  */

Color   probe_color_invert   (Color c)              { return (Color){ (uint8_t)(255 - c.r), (uint8_t)(255 - c.g), (uint8_t)(255 - c.b), c.a }; }
Vector2 probe_vector2_add    (Vector2 a, Vector2 b) { return (Vector2){ a.x + b.x, a.y + b.y }; }
float   probe_rectangle_area (Rectangle r)          { return r.width * r.height; }
Vector2 probe_touch_position (int i)                { return (Vector2){ 12.5f * (float)i, 34.25f }; }   /* GetTouchPosition's shape */
float   probe_camera_zoom    (Camera2D c)           { return c.zoom + c.offset.x; }
#+end_src

** The probe

Descriptors are literals at every use — =defcfn= and =layout= are macros that
want the shape at compile time, so a =def='d descriptor cannot be spliced in.
=write-field= / =read-field= rather than raw =ffi/write=, whose argument order
changed in 0.8.0 (raylib-jlt's =deps.edn= says so); the field forms are stable
across both.

#+begin_src clojure :tangle ../../src/probe/core.clj :mkdirp true :comments link
(ns probe.core
  "examples/flappy milestone 0: raylib's by-value struct shapes through jolt.ffi,
  on the simulator (native Chez, its own stubs) and the phone (pb: every call
  through libffi). Prints one line per case and a tally."
  (:require [jolt.ffi :as ffi]))

(def color-l  (ffi/layout [:struct [[:r :uint8] [:g :uint8] [:b :uint8] [:a :uint8]]]))
(def vec2-l   (ffi/layout [:struct [[:x :float] [:y :float]]]))
(def rect-l   (ffi/layout [:struct [[:x :float] [:y :float] [:width :float] [:height :float]]]))
(def camera-l (ffi/layout [:struct [[:offset [:struct [[:x :float] [:y :float]]]]
                                    [:target [:struct [[:x :float] [:y :float]]]]
                                    [:rotation :float] [:zoom :float]]]))

;; a by-value RETURN takes the destination pointer as the first jolt argument
(ffi/defcfn color-invert "probe_color_invert"
  [[:by-value [:struct [[:r :uint8] [:g :uint8] [:b :uint8] [:a :uint8]]]]]
  [:by-value [:struct [[:r :uint8] [:g :uint8] [:b :uint8] [:a :uint8]]]])
(ffi/defcfn vector2-add "probe_vector2_add"
  [[:by-value [:struct [[:x :float] [:y :float]]]] [:by-value [:struct [[:x :float] [:y :float]]]]]
  [:by-value [:struct [[:x :float] [:y :float]]]])
(ffi/defcfn rectangle-area "probe_rectangle_area"
  [[:by-value [:struct [[:x :float] [:y :float] [:width :float] [:height :float]]]]] :float)
(ffi/defcfn touch-position "probe_touch_position"
  [:int] [:by-value [:struct [[:x :float] [:y :float]]]])
(ffi/defcfn camera-zoom "probe_camera_zoom"
  [[:by-value [:struct [[:offset [:struct [[:x :float] [:y :float]]]]
                        [:target [:struct [[:x :float] [:y :float]]]]
                        [:rotation :float] [:zoom :float]]]]] :float)

(defn- put! [p l & kvs] (doseq [[k v] (partition 2 kvs)] (ffi/write-field p l k v)) p)
(defn- v2 [p] [(ffi/read-field p vec2-l :x) (ffi/read-field p vec2-l :y)])

(defn- check [name got expect]
  (println (format "  %-34s %s   got %s, expected %s" name (if (= got expect) "PASS" "FAIL") (pr-str got) (pr-str expect)))
  (= got expect))

(defn -main [& _]
  (println "probe:" (System/getProperty "os.arch") "— structs by value")
  (let [results
        [(ffi/with-layout [in color-l]
           (ffi/with-layout [out color-l]
             (put! in color-l :r 10 :g 20 :b 30 :a 255)
             (color-invert out in)
             (check "Color 4 B, in and out" (mapv #(ffi/read-field out color-l %) [:r :g :b :a]) [245 235 225 255])))
         (ffi/with-layout [a vec2-l]
           (ffi/with-layout [b vec2-l]
             (ffi/with-layout [out vec2-l]
               (put! a vec2-l :x 1.5 :y 2.25)
               (put! b vec2-l :x 0.25 :y 1.5)
               (vector2-add out a b)
               (check "Vector2 8 B HFA, two in, one out" (v2 out) [1.75 3.75]))))
         (ffi/with-layout [r rect-l]
           (put! r rect-l :x 0.0 :y 0.0 :width 3.0 :height 4.5)
           (check "Rectangle 16 B HFA, in" (rectangle-area r) 13.5))
         (ffi/with-layout [out vec2-l]
           (touch-position out 2)
           (check "Vector2 returned, no struct in" (v2 out) [25.0 34.25]))
         (ffi/with-layout [c camera-l]
           (put! c camera-l [:offset :x] 0.5 [:offset :y] 0.0 [:target :x] 0.0 [:target :y] 0.0 :rotation 0.0 :zoom 2.5)
           (check "Camera2D 24 B, indirect, nested" (camera-zoom c) 3.0))]]
    (println (format "probe: %d/%d pass" (count (filter true? results)) (count results)))))
#+end_src

** Building it in

=scripts/bundle= knows the two packs; this borrows its =case= rather than
growing a knob. Two link-line details that are the whole reason the script
exists: the object is passed *as an object*, not as =-lprobe= — an archive
member nobody in C references is dropped by the linker, and Chez's lookup
happens at run time, after linking is over; and =-Wl,-export_dynamic= keeps
the executable's own globals in its export trie, where =dlsym= can find them.
RAY-007 needed =--export-dynamic= for the same reason on Android.

#+begin_src sh :tangle ../../scripts/probe :mkdirp true :comments link
# jolt probe: examples/flappy milestone 0 — by-value structs, TARGET=sim|device.
# Builds src/probe/by_value.c for the target, links it INTO the jolt executable,
# and writes Hello.app/Hello. Then: jolt install && jolt console  |  jolt device
set -eu
TARGET="${TARGET:-sim}"
EXTRA=""
case "$TARGET" in
  sim)    MACHINE=tarm64ios; PACK="$HOME/dev/pack-tarm64ios-sim"
          ARCH="-target arm64-apple-ios-simulator -isysroot $(xcrun -sdk iphonesimulator --show-sdk-path)" ;;
  device) MACHINE=tpb64l;    PACK="$HOME/dev/pack-tpb64l-ios"; EXTRA="-lffi"
          ARCH="-target arm64-apple-ios14.0 -isysroot $(xcrun -sdk iphoneos --show-sdk-path)" ;;
  *) echo "TARGET must be sim or device" >&2; exit 2 ;;
esac
T=$(mktemp -d)
clang $ARCH -O2 -c src/probe/by_value.c -o "$T/by_value.o"
mkdir -p Hello.app
JOLT_TARGET_CC=clang \
JOLT_TARGET_ARCH_FLAG="$ARCH" \
JOLT_TARGET_LINK_LIBS="$T/by_value.o -Wl,-export_dynamic -L$PACK/lib -llz4 -lz $EXTRA -framework Foundation -liconv -lm" \
  jolt build -m probe.core -o Hello.app/Hello --target "$MACHINE" --target-pack "$PACK"
rm -rf Hello.app/Hello.build Hello.app/_CodeSignature Hello.app/embedded.mobileprovision "$T"
#+end_src

Same five lines, one word different. So the aggregate ABI RAY-010 deferred and
RAY-012 had to earn on Android is simply /present/ here: libffi's arm64 port
classifies HFAs and the over-16-byte indirect case the same way Chez's native
code generator does, and jolt's =[:by-value …]= sits on top of both without
caring which. Nothing in raylib's signature vocabulary is off the table on the
phone — =GetTouchPosition= included, which is milestone 3's whole input model.

Two smaller findings from the build rather than the run, both already in the
script and kept here so they are not re-learned: an object in a static archive
that no C code references is /dropped/ before Chez ever asks for it (raylib
proper will be referenced from nowhere either — milestone 1 links it with
=-force_load=, or as objects); and without =-Wl,-export_dynamic= an
executable's own globals are not in the export trie, so =dlsym= — which is
what a =defcfn= becomes at first call — cannot see them. RAY-007's
=--export-dynamic= was the same discovery on the other platform.

(One that was not learned the hard way, for once: the phone was locked for the
first launch, and =devicectl= says so plainly — "the device was not, or could
not be, unlocked" — rather than failing somewhere deeper.)

* Milestone 1: SDL and raylib, static, in the pack (2026-08-31)

Assembly before behaviour, RAY-002's rule: two static archives for the

** SDL2, in two minutes

SDL 2.32.10 from its release tarball, CMake's own iOS support, static only,
and every subsystem that would drag a framework this example does not need
turned off — audio, haptics, HIDAPI, joysticks, sensors. Video, events, timers
and the file system are what raylib's platform layer asks for.

** raylib 6.0, in three tries

=PLATFORM=SDL=, =GRAPHICS_API_OPENGL_ES2=, static, no examples. Three things
stood in the way, none of them raylib's C:

- *CMake's cross-compile find root.* With =CMAKE_SYSTEM_NAME=iOS=,
  =find_package= searches /only the sysroot/ and ignores =CMAKE_PREFIX_PATH=;
  SDL2's config directory has to be named (=SDL2_DIR=) and the find root
  widened (=CMAKE_FIND_ROOT_PATH_MODE_PACKAGE=BOTH=).
- *Widening it found the wrong SDL.* raylib prefers SDL3 when it can find one,

  compiling =raudio.c= as Objective-C; a later milestone, if ever.

* Milestone 2: the loop meets UIApplicationMain (2026-08-31)

The first real unknown. Read from SDL's source before writing anything:

- =SDL_UIKitRunApp(argc, argv, main_fn)= stores =main_fn=, then calls
  =UIApplicationMain= with =SDLUIKitDelegate=. The delegate's
  =postFinishLaunch= turns the event pump on and calls =main_fn= — on the main
  thread, inside the run loop — and when it returns it deliberately does
  /not/ =exit= ("to support applications that do setup in their main function
  and then allow the Cocoa event loop to run").
- The pump, =UIKit_PumpEvents=, spins =CFRunLoopRunInMode= until nothing is
  pending. That is what makes a /blocking/ loop legal on iOS: every
  =EndDrawing= → =PollInputEvents= → =SDL_PumpEvents= gives UIKit its turn.
  RAY-009's shape — jolt owns the =while= — survives.
- raylib's =InitPlatform= asks =SDL_Init= for =VIDEO | TIMER | EVENTS |
  GAMECONTROLLER=. Game controllers imply joysticks, which milestone 1 had
  compiled out; =SDL_Init= would have failed and =InitWindow= bailed before
  the first frame. SDL is rebuilt with =SDL_JOYSTICK=ON= (HIDAPI still off,
  so no CoreBluetooth), which brings CoreHaptics, CoreMotion and
  GameController onto the link line — the recipe and =scripts/raylib= above
  say so now.
- =InitWindow(w, h)= /is/ raylib's screen size; SDL on iOS makes the window
  full-screen whatever is asked, so asking for the display's own size is the
  honest request. =SDL_GetCurrentDisplayMode= answers before there is a
  window (its =SDL_Init= is reference-counted; raylib's second call is free).

So the shape is =screen.core= again: a =:blocking= call into UIKit's loop, a
=:collect-safe= foreign-callable that UIKit calls back into — except this
time the callable never returns, because it /is/ the program. =EndDrawing=
is declared =:blocking= too: it waits for vsync, and a wait the runtime can
see does not pin the collector for sixteen milliseconds a frame.

Colours travel as raylib-jlt's packed =:uint= (=r | g<<8 | b<<16 | a<<24=): a
4-byte struct and a =uint32= occupy one register identically, and milestone 0
says =[:by-value …]= is there when a real struct is needed.

spike with the scene factored out. Left as written, including its raw

(defn- view-framebuffer
  "SDL's drawable FBO for the current window, via SDL_SysWMinfo:
  {SDL_version version(3 B); int subsystem @4; union @8: {UIWindow *window @8;
  GLuint framebuffer @16; GLuint colorbuffer @20; GLuint resolveFramebuffer @24}}.
  The version must be filled in before the call, or SDL refuses."
  []
  (ffi/with-alloc [info 128]
    (dotimes [i 128] (ffi/write info :uint8 i 0))
    (ffi/write info :uint8 0 2) (ffi/write info :uint8 1 32) (ffi/write info :uint8 2 10)   ; SDL 2.32.10
    (if (pos? (sdl-get-window-wm-info (sdl-gl-get-current-window) info))
      {:subsystem (ffi/read info :int 4) :framebuffer (ffi/read info :uint32 16) :colorbuffer (ffi/read info :uint32 20)}
      (do (println "window: SDL_GetWindowWMInfo failed:" (sdl-get-error)) nil))))

      [(ffi/read m :int 4) (ffi/read m :int 8)]

** Four findings on the way to a frame

The first run drew nothing and reported 82,500 frames in twelve seconds at
"0 fps, dt 0.0". Four separate things were wrong, found in this order, each
one uncovering the next.

*=CUSTOMIZE_BUILD= turns the disabled options on.* raylib's =config.h= spells
a disabled option =#define SUPPORT_X 0 // Disabled by default=, and the parser
behind =CUSTOMIZE_BUILD=ON= reads any =#define SUPPORT_*= as ON, value
ignored. So =SUPPORT_CUSTOM_FRAME_CONTROL= was on — under which =EndDrawing=
does no swap, no timing and no event poll, and =GetFPS= returns a literal 0 —
and =SUPPORT_BUSY_WAIT_LOOP= with it. (The other casualties are a dozen image
formats and GPU skinning: bloat, not behaviour.) Both are explicit =OFF= in
the recipe now; a =GetTime= that advanced while =GetFrameTime= stayed 0.0 was
the tell.

*The console is a leash, again, and SDL makes it polite.* With polling
restored the loop ran at 60 fps for exactly as long as =simctl launch
--console= was attached: ending the console signals the app, SDL's signal
handler posts =SDL_QUIT=, raylib sets =shouldClose=, and the loop closed the
window and returned — after which SDL's delegate, true to its comment, did
not exit, and left a black window behind. Milestone 3 of the main notebook
found the same leash; this time it looked like a rendering bug for an hour.

*iOS has no default framebuffer.* SDL's =README-ios= says it in one line: the
drawable FBO "must be bound while rendering to the screen and when
=SDL_GL_SwapWindow()= is called", and the colour renderbuffer too. raylib's SDL
platform never binds either, so it draws into framebuffer 0 — which the
simulator's GLES obligingly treats as a valid, invisible framebuffer, and a
device would reject. The ids come out of =SDL_SysWMinfo= (=uikit.framebuffer=,
=uikit.colorbuffer=; the struct's =version= must be filled in first) and are
bound every frame. Worth an issue upstream: =rcore_desktop_sdl.c= is one
=SDL_GetWindowWMInfo= away from iOS.

*The simulator no longer shows OpenGL ES at all.* With all three fixed the
frame was provably there — a =glReadPixels= after flushing the batch read the
maroon circle at the centre and =RAYWHITE= in the corner — and the screen
stayed black. The view hierarchy was exactly right (one =SDL_uikitwindow=, an
=SDL_uikitopenglview= with a =CAEAGLLayer=, full frame, not hidden). This is
Apple's, and known: from the iOS 17.5 simulator on, EAGL apps present black
or exit — SDL2 is named specifically — while the same build renders on
hardware ([[https://developer.apple.com/forums/thread/803483][forums.developer.apple.com/thread/803483]]; the iOS 16 beta broke
=presentRenderbuffer= the same way, [[https://forums.developer.apple.com/forums/thread/707644][thread 707644]], [[https://github.com/mousebird-consulting-inc/WhirlyGlobe/issues/1542][WhirlyGlobe#1542]]). OpenGL ES
has been deprecated since iOS 12; the simulator is where the deprecation is
now enforced by neglect.

* Milestone 3: touch (2026-09-01)

Two things read before writing, both from =rcore_desktop_sdl.c=:

- =FLAG_WINDOW_HIGHDPI= "is not supported on PLATFORM_DESKTOP_SDL" — the flag
  still asks SDL for =ALLOW_HIGHDPI= (a 3× drawable), but raylib then sets
  =render = screen= and never scales. So the 3× render is done by hand: ask
  =UIScreen= for its scale, ask =InitWindow= for the display size /in pixels/,
  and SDL's always-fullscreen window makes the drawable match exactly. Screen
  units are pixels from then on; touch coordinates come out in the same units,
  because raylib scales SDL's normalised finger positions by the screen size.
- raylib sets =SDL_HINT_TOUCH_MOUSE_EVENTS= to =0= and consumes =SDL_FINGER*=
  itself: touch count, per-point ids, point-zero =GetTouchX=/=GetTouchY= — the
  scalar surface RAY-010 built on. A /press edge/ is the touch count going
  0 → 1 in the frame reducer, RAY-018's flap; =IsMouseButtonPressed= is not
  the source here.

The milestone-2 spike becomes a host: =raylib.host/run!= takes
={:title :init :frame}= and owns everything iOS — =SDL_UIKitRunApp=, the
callable, =InitWindow=, the FBO binding — and calls =(frame state)= between
=BeginDrawing= and =EndDrawing=. The scene is a reducer over frames. That is
RAY-018's owner-loop contract, and it is what =flappy_bird.cljc= will sit
under unchanged.

The simulator cannot show any of this, so the witness is the console, as it
was logcat for RAY-010: every press edge prints its coordinates from both the
scalar API and the by-value =GetTouchPosition= — milestone 0's promise, kept
in production — and every release prints how many frames the finger held.

(defn- view-framebuffer
  "SDL's drawable FBO and colour renderbuffer for the current window, via
  SDL_SysWMinfo (version @0, subsystem @4, uikit.framebuffer @16, colorbuffer @20).
  Only the version is ours to write — SDL fills the rest — and it goes through a

(defn- sdl-main
  "SDL_main: the main thread, inside UIApplicationMain, event pump on. Sizes
  the screen in pixels, then owns the loop for the life of the app."
  [_argc _argv]
  (let [{:keys [title init frame fps] :or {fps 60}} @app
        [pw ph] (display-points)
        k       (screen-scale)
        w       (int (* pw k))
        h       (int (* ph k))]
    (set-config-flags FLAG-WINDOW-HIGHDPI)       ; SDL_WINDOW_ALLOW_HIGHDPI: a full-resolution drawable
    (sdl-set-hint "SDL_FRAMEBUFFER_ACCELERATION" "metal")   ; the software rasteriser's surface: present through Metal, never GLES
    (init-window w h title)                      ; ...and a screen the same size, so raylib never scales
    (set-target-fps fps)
    (let [{:keys [framebuffer colorbuffer]} (view-framebuffer)]
      (ffi/with-alloc [dw 4]
        (ffi/with-alloc [dh 4]
          (sdl-gl-get-drawable-size (sdl-gl-get-current-window) dw dh)
          (println "host:" pw "x" ph "points × scale" k "→ screen" (get-screen-width) "x" (get-screen-height)
                   "drawable" (ffi/read dw :int 0) "x" (ffi/read dh :int 0) "fbo" framebuffer
                   "safe-area top" (safe-area-top) "pt")))
      ;; milestone 5's numbers: every 300 frames, the mean and worst frame time
      (loop [state (init {:width w :height h :scale k :inset-top (int (* k (safe-area-top)))}) n 0 sum 0.0 worst 0.0]
        (begin-drawing)
        (when framebuffer (gl-bind-framebuffer GL-FRAMEBUFFER framebuffer))
        (let [state' (frame state)]
          (when colorbuffer (gl-bind-renderbuffer GL-RENDERBUFFER colorbuffer))
          (end-drawing)
          (let [dt    (get-frame-time)
                n     (inc n)
                sum   (+ sum dt)
                worst (max worst dt)]
            (when (zero? (mod n 300))
              (println (format "host: %d frames, mean %.2f ms, worst %.1f ms, %d fps"
                               n (* 1000.0 (/ sum 300)) (* 1000.0 worst) (get-fps))))
            (if (pos? (window-should-close))
              (do (close-window) 0)
              (recur state' n (if (zero? (mod n 300)) 0.0 sum) (if (zero? (mod n 300)) 0.0 worst)))))))))

(ns raylib.touch
  "examples/flappy milestone 3: RAY-010's scalar touch polling, on the host.
  Press edges (touch count 0 → 1) and releases are counted and logged; the
  console is the witness the simulator can no longer be."
  (:require [raylib.host :as rl]))

(defn- init [{:keys [scale]}]
  {:k scale :touches 0 :presses 0 :releases 0 :held 0 :last nil})

(defn- px [k v] (int (* k v)))

(defn- frame [{:keys [k touches] :as s}]
  (let [n         (rl/get-touch-point-count)
        down?     (pos? n)
        x         (rl/get-touch-x)
        y         (rl/get-touch-y)
        pressed?  (and down? (zero? touches))
        released? (and (not down?) (pos? touches))
        s         (cond-> (assoc s :touches n)
                    down?     (assoc :last [x y])
                    pressed?  (-> (update :presses inc) (assoc :held 0))
                    down?     (update :held inc)
                    released? (update :releases inc))]
    (when pressed?
      (println "touch: press" (:presses s) "at" x y "— GetTouchPosition" (rl/touch-position 0) "id" (rl/get-touch-point-id 0)))
    (when released?
      (println "touch: release" (:releases s) "after" (:held s) "frames, last" (:last s)))
    (rl/clear-background rl/RAYWHITE)
    (let [f (px k 20) m (px k 24)]
      (rl/draw-text "touch me" m (px k 100) f rl/DARKGRAY)
      (rl/draw-text (str "touches " n "  presses " (:presses s) "  releases " (:releases s)) m (px k 140) f rl/DARKGRAY)
      (rl/draw-text (str "at " x "," y "   " (rl/get-fps) " fps") m (px k 180) f rl/DARKGRAY))
    (when-let [[lx ly] (:last s)]
      (rl/draw-circle-lines lx ly (* 40.0 k) rl/LIGHTGRAY))
    (when down?
      (rl/draw-circle x y (* 40.0 k) rl/MAROON)
      (rl/draw-circle-lines x y (* 60.0 k) rl/DARKGRAY))
    s))

(defn -main [& _]
  (rl/run! {:title "touch" :init init :frame frame}))

#+begin_src clojure :tangle ../../src/poc/raylib/flappy_bird.cljc :mkdirp true
(ns poc.raylib.flappy-bird
  "Pure, deterministic, touch-first Flappy Bird simulation.

  Adapted from the pinned raylib-jlt flappy-bird example's gameplay, but not
  its window ownership or frame-based simulation. The Raylib host supplies one
  normalized input snapshot and delta time per frame; this namespace carries no
  polling, native values, or drawing calls.")

(def max-delta-seconds 0.05)
(def default-seed 1337)

(defn dimensions
  "Derive all gameplay geometry and rates from live screen metrics."
  [metrics]
  (let [[width height] (:screen metrics)
        scale (/ (double (min width height)) 450.0)
        size (fn [n] (max 1.0 (* n scale)))]
    {:width (double width)
     :height (double height)
     :bird-x (* 150.0 scale)
     :bird-radius (size 14)
     :gravity (* 1440.0 scale)
     :flap-velocity (* -420.0 scale)
     :pipe-width (size 70)
     :gap-height (size 140)
     :pipe-spacing (size 300)
     :scroll-speed (* 180.0 scale)
     :edge-margin (size 80)}))

(defn- next-random [seed]
  (mod (+ (* 1103515245 (long seed)) 12345) 2147483648))

(defn- gap-from-seed [seed {:keys [height gap-height edge-margin]}]
  (let [minimum edge-margin
        maximum (max minimum (- height edge-margin gap-height))
        span (inc (long (- maximum minimum)))]
    [(/ (double (+ minimum (mod seed span))) 1.0) (next-random seed)]))

(defn- pipe [x seed dims]
  (let [[gap next-seed] (gap-from-seed seed dims)]
    [{:x (double x) :gap gap :scored? false} next-seed]))

(defn new-game
  "Create a reproducible game for metrics and an optional integer seed."
  ([metrics] (new-game metrics default-seed))
  ([metrics seed]
   (let [{:keys [width height pipe-spacing]} (dimensions metrics)
         ;; Keep the first obstacle visible on a phone-sized initial frame;
         ;; later pipes preserve the stable metric-scaled spacing.
         first-x (* 0.75 width)]
     (loop [index 0
            seed (long seed)
            pipes []]
       (if (= index 3)
         {:seed seed
          :elapsed 0.0
          :y (/ height 2.0)
          :vy 0.0
          :score 0
          :over? false
          :pipes pipes}
         (let [[next-pipe next-seed]
               (pipe (+ first-x (* index pipe-spacing)) seed (dimensions metrics))]
           (recur (inc index) next-seed (conj pipes next-pipe))))))))

(defn activate? [input]
  (or (= :press (get-in input [:pointer :phase]))
      (true? (get-in input [:keyboard :activate?]))))

(defn clamp-delta [delta]
  (max 0.0 (min max-delta-seconds (double (or delta 0.0)))))

(defn- collides? [y {:keys [x gap]} {:keys [bird-x bird-radius pipe-width gap-height]}]
  (and (< (- bird-x bird-radius) (+ x pipe-width))
       (> (+ bird-x bird-radius) x)
       (or (< (- y bird-radius) gap)
           (> (+ y bird-radius) (+ gap gap-height)))))

(defn- move-pipes [pipes seed dims dt]
  ;; Replacements use the previous frame's rightmost position. At most one pipe
  ;; can leave during a clamped frame with the configured spacing.
  (let [rightmost (apply max (map :x pipes))]
    (loop [remaining pipes
           seed seed
           moved []]
      (if-let [current (first remaining)]
        (let [next-x (- (:x current) (* (:scroll-speed dims) dt))]
          (if (< next-x (- (:pipe-width dims)))
            (let [[replacement next-seed] (pipe (+ rightmost (:pipe-spacing dims)) seed dims)]
              (recur (rest remaining) next-seed (conj moved replacement)))
            (recur (rest remaining) seed (conj moved (assoc current :x next-x)))))
        [moved seed]))))

(defn- score-pipes [pipes bird-x pipe-width]
  (reduce (fn [[score updated] pipe]
            (if (and (not (:scored? pipe)) (< (+ (:x pipe) pipe-width) bird-x))
              [(inc score) (conj updated (assoc pipe :scored? true))]
              [score (conj updated pipe)]))
          [0 []] pipes))

(defn step
  "Advance one frame. A press edge flaps once; when over, that edge restarts.

  Position uses constant-acceleration integration, so uncollided fixture runs
  have equivalent positions across 30/60/variable frame partitions. Lifecycle
  spikes are explicitly capped at `max-delta-seconds`."
  [state input]
  (let [metrics (:metrics input)
        dims (dimensions metrics)
        flap? (activate? input)
        dt (clamp-delta (:delta-seconds input))]
    (cond
      (:over? state) (if flap? (new-game metrics (:seed state)) state)
      (zero? dt) state
      :else
      (let [initial-vy (if flap? (:flap-velocity dims) (:vy state))
            next-y (+ (:y state) (* initial-vy dt) (* 0.5 (:gravity dims) dt dt))
            next-vy (+ initial-vy (* (:gravity dims) dt))
            [moved-pipes next-seed] (move-pipes (:pipes state) (:seed state) dims dt)
            [passed scored-pipes] (score-pipes moved-pipes (:bird-x dims) (:pipe-width dims))
            collision? (or (< (- next-y (:bird-radius dims)) 0.0)
                           (> (+ next-y (:bird-radius dims)) (:height dims))
                           (some #(collides? next-y % dims) scored-pipes))]
        (assoc state
               :seed next-seed
               :elapsed (+ (:elapsed state) dt)
               :y next-y
               :vy next-vy
               :pipes scored-pipes
               :score (+ (:score state) passed)
               :over? (boolean collision?))))))

(defn ^:export scene
  "Gallery scene descriptor. Rendering remains in the owner-affine host."
  []
  {:id :flappy-bird
   :title "Flappy Bird"
   :init (fn [input] [(new-game (:metrics input)) [[:scene/init :flappy-bird]]])
   :update (fn [state input] [(step state input) []])
   :draw (fn [state _] [state []])
   :dispose (fn [state] [state [[:scene/dispose :flappy-bird]]])})

** The iOS owner loop

Their desktop adapter (=flappy_desktop_smoke.clj=) is the model: build the
snapshot, call =step=, draw from =dimensions= and the state. Here the snapshot's
=:pointer :phase= is the touch count's edge — 0 → 1 is =:press=, held is
=:down=, nothing is =:idle= — and the delta is =GetFrameTime=, which =step=
clamps itself. Drawing is the adapter's, translated to =raylib.host='s
bindings and scaled text. Every flap and every game over goes to the console,
because that is where the simulator would have been.

#+begin_src clojure :tangle ../../src/raylib/flappy.clj :mkdirp true :comments link
(ns raylib.flappy
  "examples/flappy milestone 4: the Android experiment's pure Flappy Bird,
  unchanged, under the iOS owner loop. The host hands this one input snapshot
  and a delta per frame (RAY-018's contract); it draws what comes back."
  (:require [poc.raylib.flappy-bird :as flappy]
            [raylib.host :as rl]))

(def DARKGREEN (rl/rgba 0 117 44 255))
(def GOLD      (rl/rgba 255 203 0 255))

(defn- metrics [] {:screen [(rl/get-screen-width) (rl/get-screen-height)]})

(defn- init [{:keys [scale]}]
  {:k scale :touches 0 :frame 0 :game (flappy/new-game (metrics) flappy/default-seed)})

(defn- phase
  "The touch count's edge, as the sim's pointer phase."
  [n previous]
  (cond (and (pos? n) (zero? previous)) :press
        (pos? n)                         :down
        :else                            :idle))

(defn draw-game!
  "Draw one game state at scale k for metrics m. Public: examples/gallery draws
  the same scene through the contract's draw-scene!."
  [k game m]
  (let [{:keys [height bird-x bird-radius pipe-width gap-height]} (flappy/dimensions m)
        px (fn [v] (int (* k v)))]
    (rl/clear-background rl/SKYBLUE)
    (doseq [{:keys [x gap]} (:pipes game)]
      (rl/draw-rectangle (int x) 0 (int pipe-width) (int gap) DARKGREEN)
      (rl/draw-rectangle (int x) (int (+ gap gap-height)) (int pipe-width)
                         (int (- height gap gap-height)) DARKGREEN))
    (rl/draw-circle (int bird-x) (int (:y game)) (double bird-radius) GOLD)
    (rl/draw-text (str "score " (:score game) "   " (rl/get-fps) " fps") (px 24) (px 80) (px 20) rl/DARKGRAY)
    (when (:over? game)
      (rl/draw-text "GAME OVER - TAP TO RESTART" (px 24) (int (/ height 2.0)) (px 22) rl/MAROON))))

(defn- draw! [{:keys [k game]} m] (draw-game! k game m))

(defn- frame [{:keys [touches game] :as s}]
  (let [m     (metrics)
        n     (rl/get-touch-point-count)
        input {:metrics m
               :delta-seconds (rl/get-frame-time)
               :pointer {:phase (phase n touches)}
               :keyboard {:activate? false}}
        game' (flappy/step game input)
        s'    (assoc s :touches n :game game' :frame (inc (:frame s)))]
    (when (= :press (get-in input [:pointer :phase]))
      (println "flappy: flap at frame" (:frame s') "score" (:score game') (if (:over? game) "(restart)" "")))
    (when (and (:over? game') (not (:over? game)))
      (println "flappy: game over at frame" (:frame s') "score" (:score game')
               "elapsed" (format "%.1f" (:elapsed game')) "s"))
    (draw! s' m)
    s'))

(defn -main [& _]
  (rl/run! {:title "Flappy Bird" :init init :frame frame}))
#+end_src
